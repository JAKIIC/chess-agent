## 2. 安装与防护

安装器执行以下顺序：

1. 只接受 HTTPS 的官方 GitHub 发布地址和完整固定提交。
2. 流式下载到临时文件，同时避免直接暴露不完整的最终文件。
3. 同时核验文件大小与 SHA-256。
4. 解压前枚举成员并拒绝绝对路径、盘符和 `..` 越界。
5. 先解压到临时目录，成功后原子发布到版本目录。
6. 验证 GPL、NNUE 使用声明和网络文件均存在。
7. 按性能顺序逐个启动 Windows 构建，通过真实 UCI 握手后才选用。
8. 将相对路径写入 Git 忽略的 `current.json`，避免本地绝对路径进入仓库。

本机 `avx512icl` 和 `vnni512` 构建因 CPU 指令不兼容被安全拒绝，最终选中
`pikafish-avxvnni.exe`。

## 3. Unicode 工作区修复

第一次真实分析发现，Pikafish 从标准输入接收含中文目录的绝对 `EvalFile` 路径时
无法加载网络，随后终止。适配器现改为：

- 在 NNUE 所在目录启动子进程；
- UCI 只传 `pikafish.nnue` 文件名；
- 启动前验证网络文件存在；
- 保留 `CREATE_NO_WINDOW`、无 shell 启动和有界退出。

新增带中文目录的集成回归测试，确保该路径不会再次退化。

## 6. 尚未解除的门槛

- 尚缺 3～5 个真实合法单步的端点小样本，视觉严格接受率不能宣称通过。
- Pikafish 当前只有内核和本机资产，还未连接到面向用户的独立窗口。
- DeepSeek 尚未接入；任何解释层仍必须只消费已验证引擎证据。
- 不允许在真人在线对局使用；也不实现点击、自动走棋、注入或内存读取。

下一开发批应先建立最小独立窗口，把“当前确认局面 → 快速三候选 → 加深覆盖 →
取消旧结果”可视化；随后再接入证据约束的本地解释与 DeepSeek 降级链。
