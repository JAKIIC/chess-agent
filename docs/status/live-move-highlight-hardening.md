# 真实走棋高亮兼容加固

**日期：** 2026-08-31  
**分支：** `develop`  
**状态：** 自动验证通过；第二次现场闭环因 Windows 自动锁屏中止，待解锁后复测

## 目标

修复真实人机走棋暴露出的三类界面暂态，同时保持“宁可暂停也不误同步”的原则：

1. 第一次点击棋子后，选中态和绿色合法落点会形成短暂稳定画面；
2. 棋子从一个交点移动到另一个交点后，位置、阴影和官方高亮会改变；
3. 上一回合起终点高亮在下一步消失，会在候选端点之外产生较大帧差。

没有降低既有 `0.02` 语义间距、`0.8` 语义证据或唯一合法着安全门。

## 实现

### 选中态继续观察

`StableMoveTracker` 现在把“只有一个端点发生变化”的稳定过渡视为尚未完成的点击交互，并返回独立的 `WAITING_FOR_ENDPOINT` 状态。它保持最后确认局面和确认帧，探针继续使用 20 FPS 突发采样等待第二个端点，不再立即暂停或退回 2 FPS。两端点均变化但不能解释为唯一合法着时仍然暂停。

### 固定主题模板特征

`PieceTemplateBank` 不再按原像素位置直接比较整块裁片。每个裁片改为：

- 按颜色排序的 BGR 连续分布，消除棋子轻微平移的影响；
- 占较小权重的红色字迹优势特征，增强木纹背景下红黑阵营区分。

特征仍然连续，原有细微颜色边界测试保持有效；没有使用会把邻近颜色压入同一区间的离散直方图。

### 候选外高亮清除

观察器会先判断高帧差交点在变化后是否仍属于原来的“空位 / 红方 / 黑方”语义组。若语义未变，只把它视为界面高亮变化，不计入候选外额外走棋；若发生第二步走棋，第二步的起点必然变为空位、终点必然改变阵营或占用状态，因此仍会触发候选外变化并拒绝。

诊断样本从下一次运行起使用 `live-strict-v3`，用于区分本次特征和先前的 `v2` 样本。

- 正确候选 `a3a4` 排名第一；
