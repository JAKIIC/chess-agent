## 已完成能力

- `LiveSyncSession` 在后台拥有捕获源，建立稳定基线并连续跟踪多步。
- 每次确认走子携带 `before_position_id`；主窗口只接受与当前局面连续的更新。
- 每次窗口连接带单调会话编号；旧会话排队中的关闭或走子事件不能影响新会话。
- 主动断开或刷新会显式取消待定恢复；重连后的合法走子不会被旧恢复状态阻塞。
- 等比例窗口缩放通过固定主题局面校验后重绑 90 点；不安全缩放进入恢复暂停。
- 手工 FEN 恢复先清除旧帧，等待新的稳定帧，再原子更新跟踪器、采样器、局面和四角。
- 恢复请求使用单调编号；旧请求的排队结果和恢复期间已取出的旧帧都不能满足新请求。
- 完整 BGRA 帧使用最多 3 帧的合并队列；处理跟不上时保留最新证据，不允许无界增长。
- 捕获处理异常会关闭其拥有的捕获源，并产生一次终止状态；底层 `close()` 抛异常也不会跳过收尾。
- 黑方在下的基线会立即同步镜像方向，不需要等到第一步棋。
- Pikafish 错误携带 `position_id` 和分析代次，过期错误不能覆盖当前局面状态。
- 无 Pikafish 时仍可载入 FEN、显示棋盘并进行捕获恢复。
- 默认不保存完整截图，不把截图发送给 DeepSeek。
