# 人机实时同步高亮伪影修复（V4）

**日期：** 2026-09-01

**状态：** 实现与离线真实回放通过，等待新的可见窗口实走复验

## 问题与根因

助手能够稳定捕获天天象棋可见窗口并生成 90 个交点，但在人机连续应手后暂停在最后确认
局面。真实前后帧的最佳合法候选是：

- 红方 `h0g2`（马二进三）
- 黑方 `i9h9`（车9平8）

四个真实端点的局部差为 `26.3947–34.8973`，同时出现 `3.6107–6.6639` 的非端点
差异。后者来自当前落子光效、相邻阴影和上一手高亮消失。旧 V3 将大于 `3.0` 的任何
非端点差异都判为额外走法，并且要求着色后的端点仍在 14 类精确棋子模板中保持正边距，
因此安全冻结。

## V4 修复

- 保留合法两步枚举和唯一候选门，不根据视觉直接编造走法。
- 非端点变化只有在不超过最弱真实端点变化的 30% 时，才进入伪影复核。
- 所有超过基础门限的非端点裁片都必须仍符合确认局面的空位/红子/黑子语义。
- 强外部变化、弱但发生占用/阵营改变的变化、三步合并和候选不唯一仍拒绝。
- 精确棋子类别边距在 V2 门中改为审计值；最大模板距离和最低语义置信度继续是硬门。
- 特征版本升级为 `two-ply-template-v4`，阈值语义版本升级为
  `human-ai-two-ply-v2`；旧数据不能混入新冻结集。

## 已有证据

- 新增合成回归覆盖：弱高亮/阴影接受、弱占用语义改变拒绝、相对上限拒绝，以及语义
  置信度硬门。
- 原有强干扰、三步局面、唯一候选、吃子、回复约束和性能测试继续通过。
- 对上述真实帧离线回放得到唯一接受：`h0g2, i9h9`。
- 真实候选证据：必要变化下限 `26.3947`、最大外部差异 `6.6639`、最大模板距离
  `0.0555`、最低语义置信度 `0.8269`、候选分数 `19.7308`，拒绝原因为空。
- 本次调试帧只位于 Git 忽略的 `.local/`，不会提交或发布完整截图。
