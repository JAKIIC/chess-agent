# Accelerated Batch 1：合法走法视觉差分垂直内核

**日期：** 2026-08-30
**分支：** `develop`
**起始检查点：** `2161e57935a890f472e7b92f8be6fb6d70801ffe`
**结论：** 真实棋盘捕获、人工四角、90 点、固定主题模板提取和离线“稳定画面 → 唯一合法着 → 更新 `BoardState`”内核已经验证；监听期间没有发生可见落子，因此真实走法识别仍待一次人工落子现场验证。

## 1. 本批范围

本批只完成以下垂直内核：

```text
标准初始局面或用户 FEN
  → 可见窗口 WGC 帧
  → 人工四角和固定顺序 90 点
  → 等待动画结束和画面稳定
  → 枚举当前局面的全部合法走法
  → 对候选起点、终点和候选外变化评分
  → 唯一高置信着 / 无变化 / 歧义暂停
  → 仅在唯一着成立时 apply_move
```

没有实现完整窗口、自动棋盘定位、ONNX、Pikafish、DeepSeek、SQLite、PyInstaller、里程碑标签或自动走棋。

## 2. 实现内容

### 固定主题模板

- `PieceTemplateBank` 从已确认局面和 90 个交点裁片中提取内存模板。
- 标准初始局面可直接建立红黑 14 类棋子和空位共 15 类完整模板；用户 FEN 建立只包含当前局面实际类别的局部模板，因此残局不会因缺少已被吃掉的棋子类别而失败。
- 模板距离使用归一化 RGB 平均绝对差；模板和完整截图均不落盘。
- 差分确定候选端点后，模板语义门还会验证“起点变为空位、终点变为原移动棋子”；仅有选中或上一步高亮、但棋子没有移动时不得接受。

### 合法走法差分观察器

- `MoveObserver` 保持可替换契约，第一版实现为 `LegalMoveDiffObserver`。
- 对当前 `BoardState` 的每个 `legal_moves()` 候选计算：起点变化、终点变化、候选外最大变化和综合分数。
- 候选必须同时满足起点/终点绝对阈值、候选外变化上限、最低分数、第一名与第二名的差距门、端点模板的距离和类别间距门，以及默认不低于 0.8 的视觉/语义综合置信度门。
- 只有唯一候选通过全部门时才调用 `apply_move()`；单点变化、多步跳变和候选不唯一都返回歧义，绝不更新确认局面。
- 候选按分数和 UCI 稳定排序，输出可供诊断的前若干名，但不输出截图。

### 稳定门和安全状态机

- `StableMoveTracker` 保存最后确认帧和最后确认 `BoardState`。
- 观察到变化后先进入 `WAITING_FOR_STABLE`；只有连续稳定帧对达到要求才调用 `MoveObserver`。
- 唯一着进入 `ACCEPTED` 并原子更新确认局面；恢复原画面回到 `WATCHING`；歧义进入 `PAUSED_AMBIGUOUS` 并保持最后确认局面。
- 跟踪器不信任可替换观察器直接给出的新局面；它会再次校验合法着并自行执行 `apply_move()`，结果不一致时暂停。
- WGC 在完全静止的窗口上可能不持续回调。真实探针因此在后端之上增加“保留最新帧 + 2 Hz 时钟”：没有新帧时复用最后一帧，积压回调折叠为最新帧，关闭事件优先传播。

### 真实观察探针

`scripts/probe_move_observer.py` 只读取人工选定的 HWND、人工四角和标准初始局面或 FEN。它支持红方或黑方朝下，并确保 `BoardState` 与 90 点方向一致；先用同一 2 Hz 时钟建立稳定基线和内存模板，再等待一着，最终只输出状态、视觉/语义候选分数、UCI、中文记谱及前后 FEN/`position_id`。默认不保存任何截图。

### 基线和真实落子

- 标准初始 FEN 的 `position_id` 为 `132bdaf223100c4bd42ae8b81f0fb96c`。

## 6. 已知限制和原计划修订建议

原 spec 和 M1–M5 计划继续保留，不删除，但近期执行顺序应继续以 accelerated 垂直路线覆盖：

1. 先补一次可控的真实单步落子样本，记录真实起点、终点、候选外差分和候选间距；在取得证据前不宣称现场走法识别通过。
2. 第一版继续限定可见、无遮挡、固定主题、标准初始局面或用户 FEN、人工四角；窗口尺寸变化后要求重新标定。
3. 当前 2 Hz 时钟解决静止 WGC 不推帧的问题；检测到变化后的短暂升频仍未实现，暂不扩大到快速连续走子。
4. 人机模式可能在一次采样间隔内自动回应，形成两步跳变；系统必须保持歧义暂停。真实单步校准优先使用不会自动回应的复盘/分析画面或能控制节奏的训练模式。
5. 真实阈值尚未校准；主题、DPI、落子高亮或动画变化可能提高候选外差分。必须以真实样本调阈值，不能为了“识别成功”放宽唯一性安全门。
6. 完成真实单步闭环后，再接 Pikafish 的 500ms 快速 MultiPV 分析和最小只读结果窗口；DeepSeek、ONNX、自动定位、SQLite、PyInstaller 和十盘验收继续延后。

## 7. 下一批建议

下一步不应立即进入完整 UI 或 DeepSeek。建议先做一个很短的 Batch 1.1 现场校准：

```text
用户进入可控单步训练/复盘画面
  → 建立基线
  → 用户手工走恰好一着
  → 记录真实 top candidates 和局部差分
  → 唯一着成立则确认 BoardState 更新
  → 若歧义则保留证据并只调整视觉特征，不放宽安全门
```

该现场门通过后，下一批才进入 Pikafish 的最小垂直集成；仍不需要 DeepSeek API Key。
