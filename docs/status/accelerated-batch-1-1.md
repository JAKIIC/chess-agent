# Accelerated Batch 1.1：真实落子端点校准

**日期：** 2026-08-30
**分支：** `develop`
**起始检查点：** `4411da67eb28d1498e59c1038a6c531325ac53fc`
**结论：** 真实画面中的红方 `h2e2（炮二平五）` 和黑方 `h9g7（马8进7）` 均已恢复。两步合并时系统安全暂停；用同一组真实端点裁片在内存中重建时，两个正确走法都排在第一，但语义间距未达到既有 0.02 硬门，因此同样暂停。由于人机在中间稳定帧出现前已经回应，本批仍未取得“现场捕获的单步稳定帧”，不能宣称真实单步验收通过。

## 1. 本批目标和边界

本批只校准以下链路：

```text
真实标准初始棋盘
  → 用户手工走一着
  → 人机自动回应
  → 分析真实前后帧的局部变化
  → 两步合并必须暂停
  → 用真实端点分别验证两个唯一合法着
```

程序没有点击、自动走棋、注入或读取微信进程内存。没有接入 Pikafish、DeepSeek、SQLite、ONNX、完整窗口或打包流程。

| 交点索引 | 含义 | 局部帧差 |
|---:|---|---:|

## 4. 模板特征校准

### 发现的问题

原实现要求终点精确匹配移动棋子的字种模板。真实红炮移动到 `e2` 后，棋子阴影、棋盘背景和持续高亮改变了整块 RGB 距离：

- 红炮起点归为空位：距离 0.0332、间距 0.0410，正确。
- 红炮终点精确匹配 `C`：距离 0.1398、间距 -0.0508，错误地更接近其他红方模板。

简单圆形遮罩、二值笔画和小范围平移没有稳定恢复精确字种，直接放宽阈值会降低安全性，因此没有采用。

### 修订后的语义门

走法观察器真正需要验证的是：

1. 起点变为空位。
2. 终点变为行棋一方的棋子。
3. 起点和终点对应唯一合法着，且候选外没有明显变化。

`PieceTemplateBank.match_any()` 因此按“空位 / 红方棋子 / 黑方棋子”匹配，并使用温度 0.008、三个语义组等先验的归一化组概率。组置信度只使用每组最接近的模板，不会因为某一方当前可用字种更多而被抬高。仍保留绝对距离、0.02 组间距、视觉唯一性和最低综合置信度门。

开发过程中曾尝试把组间距门从 0.02 调到 0.01，使本次最弱样本通过；独立评审认定这是依据单一样本放宽安全条件。该修改已经撤销，并增加回归测试，确保 0.01～0.02 之间的单一样本默认只能暂停。

真实四端分组证据：

| 端点 | 正确组 | 组间距 | 组置信度 |
|---|---|---:|---:|
| 红炮起点 `h2` | 空位 | 0.0410 | 0.9938 |
| 红炮终点 `e2` | 红方 | 0.0142 | 0.8376 |
| 黑马起点 `h9` | 空位 | 0.0157 | 0.8716 |
| 黑马终点 `g7` | 黑方 | 0.0127 | 0.8277 |

四个端点的组置信度均高于 0.8，但两个终点的组间距都低于既有 0.02 硬门。语义分组改进了正确候选的排序，却没有越过安全接受条件。

## 8. 遗留风险和下一步

默认 2 FPS 加两个稳定帧对需要约 1 秒，人机可能在红方局面稳定验收前完成回应。临时 10 FPS 基线已经在两步后 FEN 上建立，但监听期间没有发生第三步，因此没有新的现场单帧证据。

下一批应先实现短时突发采样，并收集多组真实稳定单步证据，而不是立即接 Pikafish 或继续按单一样本调阈值：

```text
WGC 保持较高回调率
  → 稳态逻辑仍按 2 FPS
  → 检测到局部变化后短时按高频处理
  → 一着稳定即提交给 MoveObserver
  → 回到 2 FPS 逻辑节奏
```

突发采样取得多次真实中间稳定帧后，再比较更稳健的棋子/空位特征；只有预先锁定的门槛在独立样本上通过，才进入 Pikafish 最小集成。仍不允许自动走棋或在真人在线对局中使用。
