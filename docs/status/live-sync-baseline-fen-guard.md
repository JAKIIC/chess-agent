# 实时同步基准 FEN 安全门

日期：2026-09-01

## 结论

连接天天象棋窗口时，现在无论是否启用“帮助改进识别”，都会先在内存中核对稳定画面的 90 点占位与当前 `BoardState`。画面与 FEN 不一致时不会建立同步基准，也不会把错误局面标记为“已确认”。

“帮助改进识别”仍只控制本地小裁片的隔离保存；默认关闭时不会持久化截图或裁片。

## 根因

`CapturePanel` 原先仅在本地证据模式下创建 `KnownPositionOccupancyObserver` 并启用 `require_matching_baseline`。普通实时同步因此会把任意稳定画面直接作为已确认 FEN 的视觉基准，导致漏检后重新连接仍显示“正在监听已确认局面”。

## 修复与验证

- 普通实时同步和证据采集都启用基准占位核对。
- 证据保存与基准安全校验解耦。
- 新增回归测试：证据保存关闭时，错误画面必须产生 `CONTEXT_INVALID`，且不得产生 `BASELINE_READY`。
- 已有正确局面连接与走法同步测试继续通过。
- 聚焦捕获面板测试：`10 passed`。
- 全量测试：`590 passed, 2 skipped`。
- Ruff：通过。
- mypy：74 个源码文件通过。
- `git diff --check`：通过。
