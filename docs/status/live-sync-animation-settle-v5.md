# 实时同步动画稳定修复状态

**日期：** 2026-09-02

**分支：** `develop`

**状态：** 快速人机应手已完成一次真实原子同步；Stage C 冻结数据门仍未通过

## 结论

真实人机对局曾在棋子移动动画的短暂停顿处过早提交中间帧。该帧尚未包含最终落点，导致
合法两步候选被错误拒绝。同步采样器现在会缓存动画期间的帧，只有画面连续安静 400 ms
后才向规则观察器发布完整稳定序列。视觉门槛、唯一候选要求和失败闭锁规则均未放宽。

修复后，程序在可见且无遮挡的天天象棋人机局面中，把红方 `i0i1`（车一进一）和黑方
`h4g4`（车8平7）作为一个原子事件接受；独立诊断监听器与主界面得到完全相同的最终 FEN
和 `position_id`。这证明目标故障已在一个真实事件上消失，但不代表 30/30 Stage C 门通过。

## 根因与修复

- 动画中间帧可能连续相同约 100 ms，旧采样器会把它误认为最终稳定局面。
- 动画开始后不再把中间帧逐帧送入局面观察器，只保留最新候选终点。
- 触发突发采样仍使用既有阈值 12；稳定计时使用更敏感的阈值 3，轻微持续运动会重置安静窗口。
- 默认安静窗口由 100 ms 提高为 400 ms，并从最后一次有意义的视觉变化开始计时。
- 最终一次性发布 `stable_repeats + 1` 个相同终点帧，避免在同一动画内形成多个候选事件。
- 已确认局面的旧走法光圈在下一事件消失时，只能在最终小块仍匹配原有空位/红方/黑方
  语义并通过既有模板距离与置信门时忽略；跨阵营或占用语义变化仍会拒绝。
