# Stage C 隔离采集、事后标注与晋级设计

**日期：** 2026-09-01

**状态：** 推荐方向已获用户批准，书面规范待用户审阅

**依赖规范：**

- `docs/superpowers/specs/2026-09-01-human-ai-two-ply-sync-design.md`
- `docs/superpowers/plans/2026-09-01-human-ai-stage-c.md`
- `docs/status/human-ai-stage-c.md`

## 1. 背景与问题

现有 Stage C 采集器要求在事件开始前给出“用户一步 + 人机一步”的完整真值。用户自己的
走法可以预先确定，但人机回复通常不可预测，因此该契约适合可安排的复盘序列，不适合规模
化采集真实人机事件。

不能用以下方式规避问题：

- 不能把观察器输出直接当成真值，否则会用系统自己证明自己。
- 不能在不知道人机回复时随便预填第二步。
- 不能保存完整窗口录像后再标注，因为这超出当前隐私约束。
- 不能降低 30 个独立有效会话、30 个拒绝事件、零错误接受和 80% 覆盖率硬门。

本设计新增一个与正式样本物理隔离的生命周期：先保存不带真值的隐私安全事件，再由用户
事后确认实际走法，最后通过独立的规则、占位和完整性校验晋级。任何未复核或证据不一致的
事件都不能被冻结工具发现。

## 2. 目标与不变量

目标：

1. 用户不需要预测人机回复。
2. 用户只确认或纠正程序预填的中文走法，不接触 FEN 或内部评分。
3. 晋级后的样本仍能由现有 Stage C 决策门确定性重放。
4. 事后标签拥有可审计来源，原始证据或标签被改动后立即失效。
5. 真实有效和应拒绝事件可以在同一流程中采集，但使用不同验证规则。

继续保持：

- 不点击、不自动走棋、不注入、不读取微信进程内存。
- 用户负责所有棋盘操作。
- 不在真人在线对局中使用。
- 不保存完整窗口、完整棋盘、昵称、头像、窗口标题或 API Key。
- 未通过冻结门前，不自动把视觉局面发送给 Pikafish 或 DeepSeek。
- 未复核数据不计入任何准确率、覆盖率或延迟指标。

## 3. 三层数据边界

### 3.1 隔离事件 `QuarantinedStageCEventV1`

隔离事件描述“程序在某个稳定终点观察到了什么”，不声明正确答案。它包含：

- 匿名 `event_id`、`session_id` 和 UTC 创建时间。
- 已确认的起始 FEN、`position_id`、行棋方和棋盘方向。
- 捕获上下文、特征版本、阈值版本和终局状态。
- 最多两个观察器候选及其分数、最终 `position_id` 和拒绝原因。
- 90 个局部差异和 1–4 个最高变化交点。
- 这些交点的 48×48 前后 BGRA 小块。
- 起始和最终的 90 点棋子占位布尔值、逐点置信度及占位算法版本。
- 原始清单及每个小块的 SHA-256。

它明确不包含：

- `expected_outcome`。
- `ground_truth_moves_uci`。
- `expected_final_position_id`。
- 任何“已通过”或“应接受”字段。

目录固定为：

```text
.local/stage-c-quarantine/<session_id>/<event_id>/
```

冻结工具只接收另一个显式根目录，因此即使隔离事件字段看起来完整，也不能进入冻结集。

### 3.2 人工复核 `StageCReviewV1`

复核记录是不可变文件，包含：

- `review_id`、`event_id`、`session_id` 和 UTC 时间。
- 原始事件清单 SHA-256。
- `label_kind`：`valid_two_ply`、`expected_rejection` 或 `discard`。
- 0–3 个实际 UCI 走法。
- 有效事件的两步最终 `position_id`；拒绝事件的六类场景之一。
- 用户是否确认程序预填候选，或使用合法走法选择器进行了纠正。
- `reviewer_kind = local_user`；不保存用户姓名或账号。
- 复核界面版本和规则验证版本。

用户第一次提交复核后不能原地修改。若提交错误，只能把该复核标为撤销并创建新复核；已经
晋级或冻结的样本不能静默改写。冻结后发现标签错误必须生成新的数据集版本，并在旧报告中
留下失效原因。

### 3.3 已晋级样本 `ReviewedStageCSampleV2`

晋级样本扩展现有 `HumanAiStageCSampleV1`，增加：

- `source_event_manifest_sha256`。
- `review_manifest_sha256`。
- `label_source = post_event_local_user_review`。
- `occupancy_verifier_version`。
- `promotion_verifier_version`。
- `promoted_at_utc`。

其余候选、差异、裁片、真值、观察结果和捕获上下文字段继续使用现有语义。V2 加载器必须
严格验证全部新增字段；V1 保留只读兼容，不能通过新的事后标注入口生成。

正式候选目录固定为：

```text
.local/stage-c-reviewed/<session_id>/<sample_id>/
```

晋级采用新临时目录、完整写入、哈希复核和原子重命名。不得移动或修改原始隔离事件。

## 4. 占位证据

事后复核不能只依赖观察器候选，因此增加独立于棋子模板评分的占位证据。它不识别红黑文字，
只回答 90 个交点上是否存在圆形棋子。

### 4.1 计算方式

1. 使用已确认四角把棋盘透视展开到固定单元格大小。
2. 在每个交点附近计算圆边缘、中心/背景对比和半径一致性。
3. 输出 90 个占位布尔值和 0–1 置信度，不保存展开后的完整棋盘图。
4. 起始占位必须与已确认 FEN 的空/非空分布一致，否则不能建立可采集基线。
5. 最终占位在内存中计算后写入数值证据；只保留原有 1–4 个小块图。

该验证器是防止白屏、遮挡层或错误四角被当成基线的第二条安全边界。它不是通用棋子识别，
不取代合法走法枚举或模板门。

### 4.2 缩放与遮挡

- 每次新连接根据当前手工四角建立占位档案。
- 同一采集事件中尺寸或四角变化立即中止，不写隔离事件。
- 窗口被其他应用覆盖导致占位与 FEN 不符时，显示“目标棋盘不可见”，不建立白屏基线。
- 第一版仍不保证最小化或后台捕获；WGC 只作为后续可替换 `FrameSource`，必须单独验收后才能
  成为产品默认值。

## 5. 用户复核流程

独立窗口在终局事件后暂停同步和分析，显示一个复核卡片：

1. 显示起始镜像棋盘和程序预填的最多两步中文记谱；不显示候选分数。
2. 用户选择“走法正确”“实际走法不同”“这是应拒绝场景”或“无法确定，丢弃”。
3. “实际走法不同”按顺序提供当前局面的合法第一步和应用第一步后的合法第二步选择器；界面
   同时显示中文记谱和 UCI，但用户不需要输入 UCI。
4. “应拒绝场景”只能选择多候选、点选/悬停高亮、连续动画、遮挡、resize 或三步合并。
5. 用户提交后立即运行晋级验证；通过才显示“已进入待冻结样本”，否则保留在隔离区并解释
   哪条证据不一致。

程序候选只是减少输入工作，不是自动真值。用户确认的是刚才屏幕上实际发生的走法，而不是
“程序推荐看起来是否合理”。DeepSeek 和 Pikafish 均不参与标注。

## 6. 晋级验证

`StageCPromotionVerifier` 使用固定顺序执行以下检查，任一失败都不写正式样本。

### 6.1 通用完整性

- 原始事件、所有小块和复核记录的哈希未变化。
- ID、路径、版本、时间、FEN 和起始 `position_id` 一致。
- 数值全部有限，90 点长度正确，候选顺序确定。
- 事件尚未晋级，复核未撤销，目标样本目录不存在。

### 6.2 有效两步事件

- 恰好两步，第一步和第二步均由现有规则层从起始局面依次判定合法。
- 规则层投影得到的最终 `position_id` 等于复核记录。
- 起始占位与起始 FEN 完全一致。
- 最终占位与两步最终局面的空/非空分布在所有高置信交点上一致。
- 规则层计算的变化交点全部具有正的局部变化；若某点占位置信度不足，则事件进入
  `needs_review`，不能晋级。

这里不要求观察器已经接受或候选已经包含真值。否则会从冻结集中删掉困难样本并虚增覆盖率。
观察器拒绝真实有效两步仍可以晋级，并在评估时计为漏检。

### 6.3 应拒绝事件

- 场景必须属于冻结门要求的六类之一。
- 可以包含 0–3 个用户确认的实际走法；存在走法时每一步都必须形成合法链。
- resize、窗口关闭和捕获上下文失效优先使用机器产生的终止证据，用户不能把普通事件改标为
  这些场景。
- 三步合并必须恰好包含三步合法链。
- 多候选场景必须有至少两个可重放候选，或由占位/局部证据证明无法唯一决定。
- 高亮、动画和遮挡场景必须保持起始确认局面不被观察器提交。

拒绝标签描述“系统在该证据条件下应该拒绝”，并不等价于“棋盘上没有真实走法”。

## 7. 状态机与失败处理

事件状态只允许以下受控变化：

```text
captured -> pending_review -> promoted
                     |  |
                     |  +-> needs_review -> pending_review（提交新的不可变复核）
                     +----> discarded
```

- `captured`：原始事件已原子写入隔离区。
- `pending_review`：等待用户确认，不得自动超时晋级。
- `promoted`：V2 正式样本已原子写入 reviewed 根目录。
- `needs_review`：标签合法但占位或上下文证据不足；不能冻结。用户可以提交一份新的不可变
  复核记录，但不能覆盖旧记录。
- `discarded`：用户无法确认、误操作、损坏或重复事件。

应用崩溃后可以从隔离目录恢复 `pending_review`，但不能自动重新监听或替用户选择。临时目录、
不完整清单和哈希不符事件进入错误列表，不尝试猜测修复。

## 8. 冻结与防数据泄漏

- 冻结命令只接受 `.local/stage-c-reviewed` 或其显式子目录。
- V2 样本必须通过加载、来源哈希、复核哈希和确定性重放后才能进入冻结清单。
- 隔离根、开发集根和冻结候选根不能相同或互为父子目录。
- 冻结后不得用该数据调参；失败时只能使用独立开发集修改特征或阈值，再建立新的冻结集。
- 每个有效样本必须来自不同 `session_id`；界面显示当前独立会话进度，不用同一局的多步冒充
  30 个会话。
- 任何人工纠错都会写入来源字段，评估报告分别统计“候选直接确认”和“人工纠正”样本。

## 9. 接口边界

新增接口保持采集、复核和晋级解耦：

```python
class QuarantineEventRecorder(Protocol):
    def record(
        self,
        event: QuarantinedStageCEventV1,
        crops: tuple[TransitionPointCrops, ...],
    ) -> Path: ...

class StageCReviewStore(Protocol):
    def submit(self, review: StageCReviewV1) -> Path: ...

class OccupancyObserver(Protocol):
    def observe(
        self,
        frame: NDArray[np.uint8],
        geometry: BoardGeometry,
    ) -> OccupancyEvidence: ...

class StageCPromotionVerifier(Protocol):
    def verify(
        self,
        event_dir: Path,
        review_path: Path,
    ) -> PromotionDecision: ...

class StageCPromotionService(Protocol):
    def promote(
        self,
        event_dir: Path,
        review_path: Path,
        reviewed_root: Path,
    ) -> Path: ...
```

`LiveSyncSession` 只产生终局证据，不负责文件格式、用户标注或晋级。UI 只调用服务，不自行
复制文件、计算哈希或应用棋规。

## 10. CLI 与 UI 切片

先实现可测试的核心和 CLI，再接入独立窗口：

1. `collect_human_ai_quarantine.py`：采集一个无真值隔离事件，只打印匿名 ID。
2. `review_human_ai_stage_c.py`：列出待复核事件，使用合法走法选择器生成不可变复核记录。
3. `promote_human_ai_stage_c.py`：执行确定性验证并晋级；失败退出码与错误原因稳定。
4. Qt 复核卡片复用同一服务，替代命令行输入，但不改变数据契约。

原有事前真值采集器继续保留，供可安排的复盘序列和回归测试使用；不能让两个入口写入同一
原始根目录。

## 11. 测试门

### 11.1 单元测试

- 隔离事件不能包含真值字段，默认记录关闭。
- 占位证据为 90 点、有限、确定性且不持有完整帧引用。
- 白屏、错误四角、遮挡和与 FEN 不符的占位拒绝建立基线。
- 用户确认候选、纠正候选、有效两步、六类拒绝和丢弃流程。
- 非法走法、错误顺序、错误最终 ID、低置信占位和三步标签错误不能晋级。
- 原始事件、小块或复核文件改动后哈希校验失败。
- 重复复核、重复晋级、路径穿越、符号链接越界和目标覆盖均失败关闭。
- V1 只读兼容，V2 新增来源字段必填。

### 11.2 集成与 UI 测试

- 假帧完成 `capture -> review -> promote -> replay` 全链路。
- 真实有效但观察器拒绝的事件能够晋级，并在评估中计为漏检。
- 观察器错误接受的拒绝事件能够晋级，并在评估中计为错误接受。
- 冻结工具忽略隔离目录，只接受 reviewed 根和通过验证的 V2。
- Qt 卡片不显示候选分数，不调用引擎/教练，模式切换或局面变化使旧卡片失效。
- 进程退出、窗口关闭和重复 `close()` 不留下半写目录或后台线程。

### 11.3 隐私和发布门

- Git 不跟踪 `.local`、小块 PNG、数据库、完整截图、API Key 或二进制资产。
- 日志只包含匿名 ID、状态和稳定错误码，不打印 FEN 之外的窗口内容或标题。
- 全量 pytest、Ruff、mypy、`git diff --check` 和现有 Stage C 回归全部通过。
- 本设计本身不改变 30/30、六场景、零错误接受、80% 覆盖和 500 ms P95 发布门。

## 12. 保留期与容量

- 隔离事件默认保留 7 天，待复核事件也受容量上限约束。
- 已晋级样本默认保留 30 天，冻结操作前显示过期风险。
- 清理只删除未冻结的过期本地证据；冻结清单引用的目录不得被自动清理。
- 单个事件最多 8 张 48×48 PNG，不允许回退到完整帧或视频。

## 13. 明确非目标

- 不用 DeepSeek、Pikafish 或观察器候选自动生成真值。
- 不实现自动走棋或电脑控制。
- 不支持真人在线对局实时建议。
- 不在本切片实现通用 ONNX 棋子识别、自动棋盘定位、SQLite 或安装包。
- 不承诺遮挡、最小化或后台窗口捕获。
- 不允许“证据不足但用户点了确认”后强制晋级。

## 14. 验收标准

本设计完成的最低证明为：

1. 一个未知人机回复的真实事件可以先进入隔离区。
2. 用户事后确认或纠正两步后，合法且占位一致的事件晋级为 V2。
3. 同一事件在原始证据、标签、走法顺序、最终 ID 或小块任一项被修改后不能晋级或冻结。
4. 真实有效但系统拒绝的事件仍能进入冻结集并正确降低覆盖率。
5. 未复核、`needs_review`、`discarded` 和隔离事件不能被冻结工具发现。
6. 全流程不保存当前完整窗口截图，不触发引擎或教练。

满足这些条件只代表数据采集链可用，不代表 Stage C 已通过。只有真实冻结数据报告满足既有
全部硬门后，才能解锁实时分析。
